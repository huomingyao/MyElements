## 4. 导师团：人设、协作机制与 system prompt（→ mentors.json）

### 4.1 协作链（核心机制，程序必须严格实现）

**协作链：班主任统筹 → 调度分配 → 化学老师教学 / 助理规划 / 思维老师开脑洞。**
四位导师靠班主任统一调度串成"团队作战"，其他老师不互相 @，不绕路。

- **机制一：班主任统一接（必做）**。学生不能 @ 任何老师，不管输入什么、站在哪个房间，统一由班主任（`monitor`）首接；班主任作为调度中心判断该派给谁。
- **机制二：只有班主任能 @**。只有班主任的回复里带 @xx（可同时调度多位，如"@思维老师讲方法 + @助理列计划"）；其他老师的回复**永远不带 @**，答完协作链即终止，不再转发。
- **技术约束**：班主任调度最多 1 次（`handle_message` 返回 ≤3 条：班主任 + 至多两位被调度者，learning 类派两位时为 3），不会死循环。实现契约见 [SPEC-03 §6.1](SPEC-03-系统与接口契约.md)。

**班主任调度判断表**：

| 学生问题类型 | 分类器 | 关键词（示例，实现时可扩充） | 派给 |
|---|---|---|---|
| 怪物/危险/战斗 | `combat` | 怪、敌人、危险、攻击、掉血、幽灵、酸雾、打不过 | @思维老师（实战元素引导） |
| 学习方法/记忆 | `learning` | 怎么学、记不住、背不下、考试、复习、方法 | @思维老师 + @助理（方法+计划） |
