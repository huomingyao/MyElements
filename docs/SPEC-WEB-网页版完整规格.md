#### FR-G-07 失败反馈
`P1` · FR-G-04 · UT-G07
失败也是教学：按失败原因给不同文案。
- **AC1** 三类失败（物理混合 / 无沉淀气体水 / 条件不足）各有独立文案，不混用。
- **AC2** 连续两次同类失败不显示完全相同的文案（轮换）。

**FR-G-07 判定口径**（2026-08-02 裁决，源自 SPEC-01 FR-G-07，逐字保留）：
- 引擎只能分辨 `fail_reason` 两值（`no_match` / `wrong_condition`），分辨不出「物理混合」与「无沉淀气体水」——两者对引擎都是 `no_match`。故 AC1 落地为**按 reason 分池、池间绝不混用**：`wrong_condition` 永不取 `no_match` 池的文案，反之亦然；`no_match` 池内的两条（物理混合 / 无沉淀气体水）由轮换覆盖，即「三类文案各自独立存在且不跨池使用」。
- AC2 落地为**同一 reason 连续两次失败必须返回不同的 fail 文案 id**，实现用**确定性轮转**（每个 reason 一个计数器取模池长度），**不许用随机数**（§6.3 可测性约束：随机必须可预测）。
- 由此推出数据前提：**每个 reason 池至少 2 条**，否则 AC2 数学上不可满足。校验器按此断言。
- 第三种失败 `needs_purity_check`（命中 R4 未验纯）**不取失败池文案**，`fail_tip_id` 返回空串：这条路径由 FR-G-08 爆炸事件接管，字幕是 `sys_explosion_warn`，不是「合成失败」教学文案。失败池只服务 `no_match` / `wrong_condition` 两值。
- `try_craft` 返回的 `fail_tip_id` 是 **`fail_messages.json` 的 id，不是 `tips.json` 的 id**（失败文案不进 tips 表，避免 51 条字幕表被失败池污染）。调用方用 `RecipeDB.get_fail_message(id)` 取 text，再走 `KnowledgeTip.show_custom(text, "banner", duration)` 显示——这属于 §3.3 允许的「必须动态取文案」场景，文案仍来自数据表，未绕过 NFR-04。

`P0` · FR-G-04、FR-C-02 · IT-G08

## 2. 游戏设计

（本章内容源自 SPEC-02 全册，逐节内联；接口见 §3，文案见 §5。）

### 2.1 产品概念

**一句话**：一个 2D 横版像素开放世界，世界规则就是初中化学课本——没有魔法，只有化学。

玩家是一个小炼金术士，在一张持续存在的世界里收集真实物质、用真实反应条件合成道具、靠化学知识活下去（照明、防毒、灭火、打怪），遇到不懂的就去地图中央的「导师学院」问四位 AI 导师。

**三句收束文案**（对外统一口径，视频结尾与 PPT 都用它）：
- 对玩家：这是一个不作弊就玩不下去的游戏——而作弊方式恰好是翻开化学书。
- 对家长：他玩的每一次合成，都是考卷上要写的那条方程式。
- 对评委：我们把初中化学翻译成了游戏机制——知识不是游戏的皮肤，是游戏的物理引擎。

### 2.2 核心循环

```
探索收集 → 鉴别/合成 → 用品生存 → 卡关问导师 → 学到知识 → 更深探索
     ↑                                                        │
     └──────── 三值永远下降 + 怪物每晚刷新 = 循环永远转 ────────┘
```

**永续发动机**（区别于剧情 demo 的关键）：
- 唯一失败 = 死亡（床铺复活、掉落可捡回），没有"通关"。
- 玩家目标自定：集齐图鉴 16 种（HUD 计数口径）？挖穿矿洞？提纯粗盐？
- 资源可再生：采集物在每天清晨刷新（FR-C-04 AC4），世界采不空。

### 2.3 世界与地图

MVP：4 区 + 1 学院，**一张连续地图，不切场景**（学院为同图内的建筑内部，用区域判定区分）。

```
[盐湖]——[矿洞一层]                [导师学院]
           │ 入口在草原右侧         │ 地图中央偏上，安全区
        [草原（出生点）]——[营地]—————┘
        （草原与营地相连，营地是草原的一部分；盐湖在草原左侧，无怪物）
```

| 区域 id | 名称 | 可收集物质 | 环境机制 | 覆盖知识点 |
|---|---|---|---|---|
| `grassland` | 草原（出生） | O₂（光球）、C（木炭）、树木 | 氧气 0.5/s；白天安全，夜晚有 CO 幽灵 | 空气成分、光合作用、物理/化学变化 |
| `camp` | 营地（草原内） | 水（河边取水）、H₂/O₂（电解器）、试剂架（HCl/NaOH/Ca(OH)₂/碳口罩） | 固定设施：过滤器、电解器、合成台、篝火、床 | 水的净化四步、电解水、六大营养素 |
| `saltlake` | 盐湖（安全区） | 粗盐、湖水（硬水） | 无怪物、无氧气消耗，纯收集 + 教学区 | 粗盐提纯、硬水与软水、溶解现象 |
| `mine` | 矿洞一层 | S、CaCO₃、CuSO₄（溶液池）、Fe₂O₃ | 氧气 2.0/s（×4）；黑暗需火把；CO 幽灵全天 | 燃烧条件、CO 毒性、矿物成分 |
| `academy` | 导师学院（安全区） | 无 | 四导师常驻；怪物不入内；无消耗 | 全部知识兜底问答 |

**盐湖存在的理由**：机制最简单（无怪物、无数值威胁），铺图成本最低，但让地图从"一条线"变成"有左右探索感"，并顺手覆盖第 11 单元「盐 化肥」的粗盐提纯与硬水考点。

**区域字幕**：走近首次触发一次，文案见 §5.3.1（`zone_grass/zone_salt/zone_mine/zone_river/zone_camp/zone_academy/zone_photosynthesis`）。

#### 2.3.1 世界地图页（关键展示点）

- 入口：主菜单一个门 + 游戏内按 M / 交互营地路牌。
- 形态：手绘风世界地图底图，**13 个区域全部显示**——
  - 已解锁 5 个：彩色 + 可点击查看简介；
  - 未解锁 8 个：**灰色剪影 + 名称 + 一句预告文案 +「赛后解锁」角标**，点击时抖动一下并显示预告语，不可进入。
- 未解锁区域：深层矿洞、火山口·熔炉高地、金属矿山、酸碱沼泽、水晶矿洞、气之国、生命草原、电解实验室。
- 设计意图：评委打开地图一眼看到"完整版有 13 个区域的规划"，MVP 体量小反而成为"冰山一角"的展示优势。实现成本极低：一张底图 + 13 个按钮热区 + 一张数据表。

完整区域清单与预告文案见 §5.7。

### 2.4 系统规格与参数表

**本节所有数值均落在 `data/balance.json`（FR-D-08），改数值不改代码。** 下表是调参基线，打磨阶段以"评委 10 分钟体验到全部环节"为目标微调。

#### 2.4.1 三值系统（HUD 左上三条）

| 数值 | 键名 | 上限 | 消耗 | 回复 | 归零后果 |
|---|---|---|---|---|---|
| 氧气值 | `oxygen` | 100 | 草原/营地 0.5/s；矿洞 2.0/s；盐湖/学院 0 | 回草原/营地缓慢回满（1.0/s）；氧气瓶 +50 | 生命 5/s 持续掉 |
| 能量值 | `energy` | 100 | 0.3/s（全区一致） | 篝火进食 +40（每日限 3 次，`items.campfire_daily_limit`）；原住民交易 +20（卖装备换食物） | 移动速度 ×0.5 |
| 生命值 | `health` | 100 | 见伤害表 | 睡觉回满；篝火旁 1.0/s | 死亡 |

**氧气净速率结算规则**（消耗与回复同时作用，避免两列数值互相矛盾）：
每帧 `净变化 = 安全区回复 − 区域消耗`。安全区（草原/营地）回复 `oxygen_regen_safe`(1.0/s)、消耗 0.5/s，故净 **+0.5/s**（满值时不再增长）；矿洞无回复、消耗 2.0/s，净 **−2.0/s**；盐湖/学院两者皆 0，净 **0**。
体验上即：进矿洞掉氧、出矿洞回氧，玩家不必手动补氧就能理解「氧气只占空气 21%」这条知识点。

**伤害表**：

| 来源 | 伤害 | 免疫/对策 |
|---|---|---|
| CO 幽灵接触 | 8/s | 活性炭口罩（完全免疫） |
| 酸雾怪冲撞 | 10/次 | 中和喷雾先消灭 |
| 氢气爆炸 | 50（一次性） | 先验纯 |
| CuSO₄ 溶液池浸泡 | 5/s | 别下去（字幕警示） |
| 氧气归零 | 5/s | 回开阔地/氧气瓶 |

**每条数值变化配一条化学解释字幕**：如矿洞掉氧加快时触发 `sys_mine_breath`（"氧气不足时呼吸加快——这就是矿洞要通风的原因"）。

#### 2.4.2 昼夜循环

| 参数 | 键名 | 基线值 |
|---|---|---|
| 白天时长 | `day_duration` | 360 秒（6 分钟） |
| 夜晚时长 | `night_duration` | 180 秒（3 分钟） |
| 夜晚暗度 | `night_brightness` | 全屏压暗层到 0.35 亮度 |
| 无光源视野半径 | `dark_view_radius` | 80 px |
| 持火把视野半径 | `torch_view_radius` | 220 px |

夜晚行为：画面压暗；酸雾怪在营地外围刷新 2~3 只；无火把时视野收缩到主角周围一圈。
床交互：画面渐黑 → 直接跳到第二天清晨 → 生命回满 → 采集物刷新 → `day_count` +1。

#### 2.4.3 采集与背包

- 采集物漂浮 + 发光呼吸动画；走近按 E 拾取。
- 首次获得某物质弹出 3 秒 `bubble` 字幕（名称 + 化学式 + 一句课本性质）。
- 背包：8 格快捷栏 + 背包界面（Tab），堆叠上限 99。
- HUD 左上显示「已收集 N/16」。
- 采集物**不需要工具**（MVP 砍掉工具分层），走近即可拾取。

#### 2.4.4 合成系统

1. 营地合成台交互 → 打开合成界面。
2. 从背包拖入 2~3 个材料到合成格；选择器材：`portable`（便携格）/ `alcohol_lamp`（酒精灯）/ `bench`（实验台）。
3. 点「反应」→ 引擎查 `recipes.json`：
   - **材料 + 器材 + 条件全部匹配** → 成功：产物入包 + 弹出**知识卡片**（标题 + 方程式 + 现象 + 现实应用，可跳过）。
   - **材料对但条件/器材不对** → 失败：条件类文案（"条件不够——有些反应需要点燃、加热、通电或催化剂"）。
   - **完全不匹配** → 失败：轮换文案（"没有新物质生成——这只是物理混合，不是化学反应" / "没有生成沉淀、气体或水，所以不反应"）。
   - **「反应」按钮的条件口径**（2026-08-02 补）：器材选酒精灯时「反应」等价于 `heat`（加热，如 R12 碳活化），便携格/实验台下为 `none`；「点燃」按钮恒为 `ignite`；矿洞内点燃碳按 `low_oxygen` 匹配（R3 陷阱，见 D3 裁决），成功产出 CO 时触发一次 `warn_co` 警示。
4. 失败**不消耗材料**（对玩家友好，避免评委卡死）。
5. 每张卡片底部固定一行 `card_footer`：「反应前后原子种类和数目不变——质量守恒定律」。

12 条配方的完整内容见 §5.2。

#### 2.4.5 特殊事件：氢气验纯爆炸（全场核心记忆点）

**这是整个产品的灵魂场景，演示必演，优先级高于一切美术打磨。**

流程状态机：

```
获得 H₂ ──► 合成界面出现「点燃」
              │
              ├─ purity_check_unlocked == false ─► 直接点燃
              │      └─► 爆炸动画（屏幕震动+火光+音效）
              │            └─► 生命 -50
              │                  └─► warning 字幕 sys_explosion_warn
              │                        └─► 设 explosion_happened = true
              │
              └─ purity_check_unlocked == true ──► 出现「验纯」步骤
                     └─► 验纯（"噗"轻响 + sys_purity_ok）
                           └─► 点燃成功
                                 └─► 卡片：2H₂+O₂=点燃=2H₂O，氢能源
```

`purity_check_unlocked` 的解锁条件：向导师提问过氢气/爆炸/验纯相关问题（由导师模块回调设置，关键词读 `qa_fallback.json` 的 `qa_h2_explosion` 行，代码零中文关键词）。另有演示保险开关可强制解锁（FR-G-09 AC4）。

设计意图：**失败变成最想知道答案的瞬间**——玩家被炸一次后主动跑去问导师，这就是"知识作为游戏机制"的证明。

#### 2.4.6 怪物 ×2（每只怪 = 一道应用题）

| 怪物 | 出现条件 | 行为 | 对策（知识点） |
|---|---|---|---|
| CO 幽灵（灰色半透明） | 矿洞全天 + 草原夜晚 | 缓慢飘向玩家，接触掉血 8/s | 活性炭砸中即消散（活性炭疏松多孔、吸附毒气——防毒面具原理）；装备活性炭口罩完全免疫 |
| 酸雾怪（黄绿色雾团） | 夜晚营地外围，2~3 只 | 直线冲撞，命中 -10；撞墙后重新锁定，存活超 `monsters.acid_mist_lifetime_seconds`（200 秒）或出界即自销毁 | 中和喷雾喷中即消散（酸+碱→盐+水） |

怪物 AI 保持最简：CO 幽灵为匀速追踪（可穿墙，符合"气体"设定）；酸雾怪为锁定方向直线冲撞 + 撞墙后重新锁定。**不做寻路，不做状态机分层。**

#### 2.4.7 死亡与复活

三值任一归零或受到致命伤害 → 死亡画面（字幕 `sys_death`：「你倒下了……化学不等人」）→ 营地床铺复活，三值回满，身上物品掉在死亡地点（发光标记，可跑回捡）。**死亡是唯一的"关卡"。**

#### 2.4.8 导师学院（像素工作室式）

- 一座建筑四个房间：化学实验室 / 班主任办公室 / 自习室 / 思维工坊。**每个房间里有一位导师像素小人**（32×32，idle 两帧张合或踱步），整体观感参考像素工作室：小人站在自己的小房间里各忙各的。
- 四位导师（完整人设见 §5.4）：
  - 化学老师·袁仲衡（`chem`）— 化学实验室

## 3. 系统与接口契约（TypeScript）

（本章源自 SPEC-03 全册，按 Web 口径重写为 TS 接口。**本章在脚手架完成后冻结**：之后任何接口变更必须先改本章（含 §3.10 变更记录），再改代码。其他人只调用，不修改核心单例签名。）

### 3.1 架构总览

```
┌──────────────── core 层（src/core/ 全局单例，冻结） ─────────────────┐
│ GameManager   三值 / 昼夜 / 区域 / 死亡复活 / 全局标记                 │

│ WorldMap      13 区域状态与地图页（worldmap.json）                     │
│ EventBus      类型化事件总线（所有跨模块事件的唯一通道）                │
└───────────────────────────────────────────────────────────────────────┘
        ▲              ▲                ▲                ▲
        │ 事件/调用     │                │                │
┌───────┴──────┐ ┌─────┴──────┐ ┌───────┴──────┐ ┌───────┴──────┐
│ scenes/menu  │ │scenes/world│ │ scenes/world/ │ │  mentor/     │

                  └───────────────┘
```

**依赖方向铁律**（沿用原 SPEC-03 §1）：
- core 单例**不允许**反向依赖具体 Scene（不 import scenes/）。要通知场景，经 `EventBus` 发事件。
- 场景/模块之间**不横向直连**。跨模块通信一律走 `EventBus`。
- 数据表只由 core 单例与共享 `DataLoader` 读取；场景不自己 `fetch` 数据表。

### 3.2 GameManager（`src/core/game_manager.ts`）

职责：三值、昼夜时钟、区域判定、死亡复活、全局事件标记。

#### 3.2.1 状态

```typescript
// 三值（0..max）
oxygen: number;  energy: number;  health: number;
oxygenMax = 100; energyMax = 100; healthMax = 100;

// 时间
dayCount = 1;
timeOfDay = 0.0;      // 当前昼夜周期内已过秒数

// 全局标记（供跨模块查询，禁止其他模块直接写除 setter 外的字段）
explosionHappened = false;
purityCheckUnlocked = false;
```

#### 3.2.2 契约方法（冻结面）

| 签名 | 说明 |
|---|---|
| `tick(delta: number): void` | **唯一时间推进入口**：推进昼夜时钟 + 结算三值消耗。由 WorldScene 在 `update()` 里调用；测试可一次注入 600 秒（§6.3 可测性约束）。单例自身**不**自跑时钟 |
| `isNight(): boolean` | 当前是否夜晚 |
| `currentZone(): string` | 当前区域 id（`grassland/camp/saltlake/mine/academy`） |
| `setZone(zoneId: string): void` | 区域触发器调用；内部去重后发 `zone_changed` |
| `modifyOxygen(delta: number): void` | 增减氧气，内部 clamp + 发事件 |
| `modifyEnergy(delta: number): void` | 同上 |
| `modifyHealth(delta: number): void` | 同上；归零触发死亡流程 |
| `moveSpeedMultiplier(): number` | 能量归零返回 0.5，否则 1.0 |
| `sleepUntilMorning(): void` | 床调用：跳夜、生命回满、天数 +1、发 `resources_respawned` |
| `respawnPlayer(): void` | 复活：三值回满、位置回床、清空背包（掉落由 gameplay 处理） |
| `setFlag(key: string, value: boolean): void` | 设置全局标记（只允许 `explosion_happened` / `purity_check_unlocked`） |
| `getFlag(key: string): boolean` | 读取标记；未知 key 返回 false + 警告日志 |
| `getBalance(key: string, defaultValue: unknown): unknown` | 读 `balance.json`；缺键返回默认值 + 警告 |
| `getUiString(key: string): string` | 读 `ui_strings.json`（§4.11）；缺 key 返回 key 本身 + 警告，不崩溃 |

**非契约辅助**（实现需要，不属冻结面，调用方勿依赖）：`reloadConfig()` / `resetStats()` / `resetClock()`（时钟回第一天清晨，测试/新开局用）/ `setRespawnReferencePosition(x, y)` / `oxygenNetRate(): number`（当前区域氧气净速率，供 HUD 与测试查询）。

#### 3.2.3 约束

- 三值消耗速率、昼夜时长、伤害值全部走 `getBalance()`，**不许写死在逻辑里**。
- 界面短语走 `getUiString()`，知识字幕走 `KnowledgeTip`；两者都不许在场景/脚本里写中文字面量（NFR-04）。
- `modifyHealth` 在归零时只发 `player_died` 一次（需要内部去重，防止同帧多次伤害重复触发）。
- 区域切换必须去重：同一区域重复 `setZone` 不发事件。

### 3.3 KnowledgeTip（`src/core/knowledge_tip.ts`）

职责：字幕引擎，唯一文案出口。

| 签名 | 说明 |
|---|---|
| `show(tipId: string): void` | 按 `tips.json` 的 style/duration 显示；不存在则警告日志、不崩溃 |
| `showOnce(tipId: string): void` | 同上，但同一 id 只显示一次（用于区域/首次拾取） |
| `showCustom(text: string, style: string, duration: number): void` | 仅用于必须动态拼接的极少场景（如物质名 + 数量），**不得用来绕过数据表** |
| `isShown(tipId: string): boolean` | 是否已展示过（供测试断言） |
| `clearQueue(): void` | 清空队列（场景切换/测试用） |

事件：`tip_shown(tipId)`、`tip_finished(tipId)`。

约束：
- 内部队列串行播放，同 style 不重叠；`warning` 可打断一切在播样式（危险优先；被打断的 `once` 字幕撤销已展示记录，之后可再次触发）。
- `once` 字幕的已展示标记时机为**开播时**（不是入队时）。
- 任何模块显示文案**只能**走这里，逻辑代码里出现中文字面量视为违规（NFR-04）。

**非契约辅助**：`advance(delta: number)`（唯一时间推进入口，由字幕渲染层在 `update()` 里调；单例自身不跑时钟）、`currentTipId()` / `currentText()` / `currentStyle()`、`queueSize()`、`loadFrom(rows)`（数据注入口，`reload()` 内部调它）、`reload()`。

### 3.4 RecipeDB（`src/core/recipe_db.ts`）

职责：物质表、配方表、失败文案池的查询与匹配。

| 签名 | 说明 |
|---|---|
| `getSubstance(id: string): Record<string, unknown>` | 返回物质记录；不存在返回空对象 |
| `allSubstances(): Array<Record<string, unknown>>` | 全部 17 条（图鉴用；HUD 计数集合为其中 16 条） |
| `tryCraft(items: string[], tool: string, condition: string): CraftResult` | 核心匹配 |
| `getRecipe(id: string): Record<string, unknown>` | 按 id 取配方 |
| `unlockedRecipes(): string[]` | 已解锁（已成功合成过）的配方 id 列表，图鉴用 |
| `getFailMessage(failId: string): { id: string; reason: string; text: string } \| Record<string, never>` | 按 `fail_tip_id` 取失败文案记录；不存在返回空对象。失败池 id 只在 `fail_messages.json`，不在 `tips.json`（FR-G-07 判定口径） |
| `reload(): void` | 重新读数据表（调参/测试用） |

`CraftResult` 结构（**契约，不许改字段名**）：

```typescript
interface CraftResult {
  success: boolean;
  recipe_id: string;         // 失败为 ""
  outputs: string[];         // 失败为 []
  card: {                    // 失败为 {}
    title: string; equation: string; body: string; application: string; footer: string;
  } | Record<string, never>;
  fail_reason: "" | "no_match" | "wrong_condition" | "needs_purity_check";
  fail_tip_id: string;       // 失败时的文案 id；成功为 ""
  requires_pure_check: boolean; // 命中 R4 且未验纯时为 true
}
```

匹配规则（**测试必须逐条覆盖**）：
1. `items` 排序后与配方 `inputs` 排序比较，**材料顺序不影响结果**。
2. 材料匹配但 `tool` 或 `condition` 不符 → `success=false`，`fail_reason="wrong_condition"`。
3. 命中 `requires_pure_check` 的配方且 `GameManager.purityCheckUnlocked == false` → `success=false`，`fail_reason="needs_purity_check"`（由 gameplay 触发爆炸事件）。
4. 无任何配方材料匹配 → `fail_reason="no_match"`，`fail_tip_id` 从失败文案池按 reason 确定性轮转。
5. 匹配成功后记录该 recipe_id 为已解锁。

**非契约辅助**：`allRecipes()`（12 条配方记录，测试与图鉴用）、`allFailMessages()`、`buildCard(recipe)`（按 FR-G-06 组装卡片五字段）、`markUnlock(recipeId)`、`resetRotation()`（失败文案轮转计数器复位）、`resetUnlocked()`（已解锁进度复位，测试/新开局用）。

### 3.5 交互接口（`Interactable` 约定）

玩家交互系统不认识具体类型，只认约定。任何可交互对象必须满足：

```typescript
interface Interactable {
  getInteractPrompt(): string;   // 返回提示文本 id（走 KnowledgeTip 或 UI 短语表）
  canInteract(): boolean;        // 当前是否可交互
  interact(player: Player): void; // 执行交互
}
```

约束：
- 玩家控制器**只**调用这三个方法，新增交互物不需要改玩家代码（FR-P-02 AC3）。
- 范围内多个对象时按距离最近选择。
- `interact()` 内部不许阻塞（异步逻辑用事件/Promise，不用忙等）。

**玩家实体**（场景层，**不属冻结面**）：Phaser Arcade Sprite + 自写平台移动；挂载点：`inventory` / `itemEffects` / `getEquippedItemIds()`；`inputBlocked` 由 UI 裁决器写入；视野遮罩半径按 `dark/torch_view_radius` 切换（无纹理时用程序生成的径向渐变兜底）；加入 `player` 组供怪物定位。

### 3.6 导师模块接口（`src/mentor/`）

#### 3.6.1 MentorRouter（纯逻辑类）

纯逻辑类，**不依赖 Phaser，可被 Vitest 直接实例化**（这是 UT-M04/M05 能跑的前提）。

| 签名 | 说明 |
|---|---|
| `classify(question: string): "combat" \| "learning" \| "chemistry" \| "other"` | 分类 |
| `routeTargets(category: string): string[]` | 返回被派导师 id 数组，如 `["think","assistant"]` |
| `parseMentions(text: string): string[]` | 解析回复中的 @xx → 导师 id 数组（句柄读 `mentors.json` 的 `mention` 字段，最长句柄匹配） |
| `handleMessage(question: string): ChatMessage[]` | 完整一轮对话，返回消息序列 |

`ChatMessage` 结构：

```typescript
interface ChatMessage {
  mentor_id: string;   // "monitor" | "chem" | "assistant" | "think"
  text: string;
  offline: boolean;    // 回答来源自报在线状态（透传 LLMClient.isOffline()）
}
```

**硬约束（对应 FR-M-05）**：
- 第一条消息的 `mentor_id` **必须**是 `"monitor"`。
- 返回数组长度 ≤ 3（班主任 + 最多 2 个被派老师）。
- 只解析 `monitor` 消息中的 @；其他导师消息中的 @ 一律忽略（不触发新一轮）。
- 递归深度硬上限 1 次调度，代码层面用计数器保证，不依赖 prompt 自觉。

**非契约辅助**：`loadFrom(rows)`（数据注入口）、`setReplyProvider(provider)`（注入回复来源 `(mentorId, question) => string | { text, offline }`；空串视为离线兜底；未注入时走 `LLMClient.ask`）、`dispatchCount()`（本次调度次数的可观测点）、`systemPromptFor(mentorId)`（人设段 + 通用后缀；未知 id 返回 `""`）。

#### 3.6.3 LLMClient（`src/core/llm_client.ts`）

| 签名 | 说明 |
|---|---|
| `ask(mentorId: string, question: string, history: HistoryTurn[]): Promise<string>` | 异步调用，返回回复文本；失败自动兜底 |
| `isOffline(): boolean` | 当前是否离线模式 |
| `setOffline(value: boolean): void` | 手动切换（演示保险开关） |
| `hasApiKey(): boolean` | `localStorage`（`ea_config`）中是否有可用 key |
| `setApiKey(key: string): void` | 写入 `localStorage` |

事件：`reply_started(mentorId)`、`reply_finished(mentorId, fullText, offline)`、`mode_changed(offline)`。
（`reply_chunk` 事件名保留但**本期不发射**——DeepSeek 按非流式请求实现；调用方不得依赖它。）

约束：
- 唯一真实网络出口是私有 `_generateReply()`；测试通过注入传输层替换它，**不发真实请求**。
- 超时 8 秒 + 重试 1 次（读 `balance.json` 的 `llm.*`，测试中可调小）。
- key 只从 `localStorage` 读；**不得**出现在日志、错误消息、前端产物任何源文件（NFR-05）。
- 历史只带最近 4 轮。
- 玩家输入在进入 prompt 前必须经过 `sanitizeInput()`（截断 200 字符 + 清理控制字符与换行）。

**非契约辅助**：
- `setTransport(transport)`：注入传输层 `(payload) => Promise<{ result: number; code: number; body: string }>`，这是 `_generateReply()` 内部**唯一**发包处；`result` 为 0 表示成功，其余算失败（超时用专用码，CORS 拦截/连不上归入网络错）。
- `buildRequestBody(mentorId, question, history)`：组请求体（供 IT-M07 直接断言 `model` / `messages` / `max_tokens` / `temperature`）。
- `attemptCount()`：上一次 `ask()` 实际发包次数（离线时为 0）。
- `timeoutSeconds()` / `retryCount()` / `setTimeoutSeconds(v)` / `setRetryCount(v)`。
- `setQaFallback(qa)`：注入离线兜底表。

**四种失败**（超时 / 网络错（含 CORS 拦截）/ 非 200 / 畸形 body）一律返回空串，由 `ask()` 转入离线兜底，**不抛异常**（FR-M-08 AC2）。

**历史元素约定**：`history` 的每个元素是一**轮**对话 `{ question: string, answer: string }`，进请求体时展开为 `user` + `assistant` 两条 message。只保留最后 `llm.history_rounds`（默认 4）个元素。

**网络常量**（非玩家可见文案，属技术约束，写在 `llm_client.ts` 常量区）：
端点 `https://api.deepseek.com/chat/completions`、模型 `deepseek-chat`、鉴权头 `Authorization: Bearer <key>`（OpenAI 兼容）。`max_tokens` / `temperature` 读 `balance.json` 的 `llm.max_tokens` / `llm.temperature`（默认 300 / 0.7）。端点可被「代理 URL」覆盖（§9.4 第二层方案）。

**离线回答组装**：`_offlineReply()` = `QaFallback.answer(question)` + `ui_strings.chat_offline_badge`。兜底表为空时只返回角标，保证离线回复永不为空串。

## 4. 数据模型（10 个 JSON 文件）

（本章源自 SPEC-04 全册，逐节内联。）本章定义仓库 `data/` 下 **10 个 JSON 文件**的 Schema 与约束：`substances` / `recipes` / `fail_messages` / `tips` / `mentors` / `qa_fallback` / `worldmap` / `balance` / `items` / `ui_strings`。文案内容在 §5。
程序只认字段名；填内容时字段名一个字母都不许改。全部表格由 `FR-D-07 数据校验器`统一校验，校验不过不许提交。

### 4.1 通用约定

- 位置：仓库根 `data/*.json`，构建期由 `scripts/copy_data.ts` 原样拷贝进 `web/public/data/`（网页工程**不另存一份数据**，改内容永远改仓库根的 `data/`）。
- 编码 UTF-8 无 BOM，两空格缩进。
- 顶层结构：**数组**（`[...]`），不用带包装的对象（`ui_strings.json` 例外，为对象）；`balance.json` 为对象。
- id 命名：全小写蛇形，与化学式对应时用小写无下标（`h2o`、`caco3`、`cuso4`）。
- 化学式/方程式在文案字段中用 Unicode 下标（`O₂`、`H₂O`、`CaCO₃`），**不用 LaTeX**。
- 资源路径在数据文件里写 `res://` 前缀（与 Godot 版共用同一份数据）；**DataLoader 加载后统一把 `res://assets/` 改写为 `assets/` 相对 URL**，数据文件本身一个字节不改。缺资源时指向占位图 `res://assets/art/placeholder.png`。
- 布尔字段缺省视为 `false`；数值字段缺省由代码常量兜底并输出警告。
- **禁止在数据表中写游戏逻辑**（无表达式、无脚本路径求值）。

匹配规则（**UT-M09 逐条断言**）：
1. 对问题文本做包含匹配，统计命中的 keyword 数量（兜底行 `keywords` 为空，命中数恒为 0）。
2. 取命中数最多者。
3. **平票取表中先出现者**（结果确定可复现，不用随机）。
4. 零命中 → 返回兜底行的 `answer`（即班主任零命中话术）。
5. 「（离线模式）」后缀由调用方追加，不写进 `answer`。

校验规则：条目数 ≥20；无重复 id；`answer` 非空；恰好一行 `keywords` 为空（兜底行），其余行 `keywords` ≥1 项且无空字符串。

### 5.4 导师团：人设、协作机制与 system prompt（→ mentors.json）

#### 5.4.1 协作链（核心机制，程序必须严格实现）

**协作链：班主任统筹 → 调度分配 → 化学老师教学 / 助理规划 / 思维老师开脑洞。**
四位导师靠班主任统一调度串成"团队作战"，其他老师不互相 @，不绕路。

- **机制一：班主任统一接（必做）**。学生不能 @ 任何老师，不管输入什么、站在哪个房间，统一由班主任（`monitor`）首接；班主任作为调度中心判断该派给谁。
- **机制二：只有班主任能 @**。只有班主任的回复里带 @xx（可同时调度多位，如"@思维老师讲方法 + @助理列计划"）；其他老师的回复**永远不带 @**，答完协作链即终止，不再转发。

## 6. 测试计划（TDD 约定）

（本章源自 SPEC-06 全册，按 Web 口径重写。）本章定义"怎么证明它是对的"。每条 FR 至少一个自动化测试；测试编号与 FR 一一对应。
**RED → GREEN → REFACTOR 顺序不许颠倒**：先写测试并看到它按预期失败，再写实现。

### 6.1 测试栈与运行方式

| 项 | 选择 |
|---|---|
| 单元/数据测试 | Vitest（`web/tests/unit/`（纯逻辑）、`web/tests/data/`（数据表校验）） |
| E2E/集成测试 | Playwright（`web/tests/e2e/`），驱动真实浏览器跑构建产物或 dev server |
| 命名 | 文件 `test_<模块>.test.ts`；用例名描述行为与期望 |
| 数据校验 | `npm run validate` → `scripts/validate_data.ts`（独立于 Vitest） |

**运行命令**：

```bash
npm run test            # 全部 Vitest（单元 + 数据）
npm run test:unit       # 只跑单元测试
npm run test:e2e        # Playwright 全流程
npm run validate        # 数据表校验（输出 DATA OK）
```

约定：脚手架阶段把上述命令封进 `package.json` scripts，之后所有人只敲命令名。

### 6.2 TDD 循环的可操作定义

每个任务包（§7.5）都按这个走：

1. **读 FR** — 拿到 FR-ID 与 AC 列表。
2. **RED** — 为每条 AC 写一个测试用例；跑一遍，确认**断言失败**（不是脚本报错、不是找不到文件）。这一步没看到红色就不算 RED。
3. **GREEN** — 写最少的实现让测试变绿。不顺手重构、不提前抽象。
4. **REFACTOR** — 清理命名与重复；再跑**全量**测试确认没弄坏别的。
5. **报告** — 输出：改了哪些文件 / 跑了什么命令 / 通过多少条 / 哪条 AC 没能自动化验证（说明原因）。

**不允许的做法**：
- 先写实现再补测试（这不是 TDD，是补作业）。
- 用空测试占位换绿。
- `expect(true).toBe(true)` 之类的假测试。
- 为了让测试通过而修改 AC（AC 要改必须先改 §1 并说明理由）。

### 6.3 可测性设计约束（这是能 TDD 的前提）

| 约束 | 原因 |
|---|---|
| 纯逻辑与场景分离：`MentorRouter`、`RecipeDB` 匹配逻辑、`QaFallback` 匹配、背包结算、数值结算全部是**可独立实例化的类**，不 import Phaser | 单测能直接 `new` 出来跑 |
| 时间可注入：昼夜与三值消耗接受 `delta` 参数推进，不直接读 `Date.now()` | 测试可以一次推进 600 秒 |
| 网络可替换：`LLMClient._generateReply()` 内部唯一发包点 `setTransport`，测试注入 stub | 测试不发真实请求、不烧 token |
| 随机可控：失败文案轮换用确定性轮转（计数取模），不用 `Math.random()` | 结果可复现 |
| 数据可注入：各 DB 类支持 `loadFrom(rows)` 喂假数据 | 不依赖真实数据表的完整度 |
| 配置可覆盖：`balance.json` 的值在测试中可被覆写 | 超时 8 秒在测试里调成 0.1 秒 |
| 存储可隔离：测试注入假存储，不碰真实 `localStorage` | 不污染、可并行 |

**违反可测性约束的代码视为未完成**，即使功能能跑。

### 6.8 全流程回归脚本（每轮 bug bash 照这个跑，约 12 分钟）

1. 打开链接 → 主菜单三个门各点一次 → 开始冒险。
2. 草原捡 O₂、C → 确认字幕与计数 2/16。
3. 打开地图页（M）→ 确认 5 彩色 + 8 剪影 + 角标。
4. 去盐湖 → 捡粗盐 → 肥皂水试湖水 → 确认硬水字幕。
5. 回营地 → 河边取水 → 过滤器（四步字幕）→ 电解器（得 H₂/O₂ + 灌装氧气瓶）。
6. 合成台：木棒+S → 硫火把 + 知识卡片。
7. 合成台：H₂+O₂ 直接点燃 → **爆炸 + 扣 50 + 警示字幕**。
8. 去导师学院 → 问"为什么氢气会爆炸" → 确认班主任首接 + @化学老师 + 袁仲衡回答 + **答完终止**。
9. 追问"接下来该做什么" → 班主任 @助理 → 周启明三步计划。
10. 回合成台 → 验纯 → 点燃成功 → 卡片正确。
11. 下矿洞 → 确认氧气加速掉 → 捡 S/CaCO₃ → 硬挨 CO 幽灵一下 → 合成活性炭砸幽灵确认消散。
12. 等到夜晚 → 火把照明 → 酸雾怪出现 → 喷雾消灭。
13. 故意死一次 → 床复活 → 跑回死亡点捡回物品。
14. 睡觉跳夜 → 确认清晨、生命满、资源刷新。
15. 打开图鉴 → 确认收集进度与已解锁卡片。
16. 全程观察 console：**零未捕获异常**。

**断网版**：拔网线重跑 1–16，第 8/9 步确认回答带「（离线模式）」。

### 7.2 并行安全矩阵

| 可安全并行的组合 | 原因 |
|---|---|
| core 单例（`src/core/`）+ 导师纯逻辑（`src/mentor/`）+ 美术处理（`assets/`） | 目录不相交 |
| 玩法纯逻辑（`src/gameplay/`）+ 数据表（`data/`） | 玩法只读数据表，不写 |
| 多个数据表任务 | 一表一文件，各自独立 |

| 必须串行的组合 | 原因 |
|---|---|
| §3 冻结面接口变更 vs 任何调用方 | 接口是全局契约，只能主程改 |
| `balance.json` 的多方写入 | 单文件多写者必冲突，改动集中给主程 |
| 同一 Scene 文件的并行修改 | 合并极易坏 |

### 9.4 导师 LLM 在浏览器中的方案（两层）

**问题**：任何打进前端产物的 key 都等于公开（违反 NFR-05）；浏览器 `fetch` 调第三方 API 受 CORS 约束。

**第一层（默认，无后端）——用户自备 key：**

1. 设置页提供 key 输入框（`type="password"`，不回显——对齐 §3.6.5）。
2. key 存 `localStorage`（`ea_config`），**仅本人浏览器可见**，不进 git、不进日志、不进请求体之外的任何地方。
3. 请求直连 OpenAI 兼容端点（默认 `https://api.deepseek.com/chat/completions`，模型 `deepseek-chat`，§3.6.3 网络常量）。
4. 未填 key → 自动离线模式，体验完整（FR-M-07 AC3）。
5. **W0-3 必须实测**：目标端点在部署域下是否返回允许跨域的 CORS 响应头；若不放行，第一层退化为「必须走第二层代理」，设置页改填代理 URL。

**第二层（可选，轻量代理）——Cloudflare Workers 转发：**

适用场景：想让评委开箱即用在线导师，又不想暴露 key。真实 key 放**服务端环境变量**，前端只见代理 URL。

```javascript
// worker.js —— Cloudflare Workers 最小示例（约 40 行）
const ALLOWED_ORIGINS = ["https://<user>.github.io", "https://<your>.itch.io"];
const UPSTREAM = "https://api.deepseek.com/chat/completions";

export default {
  async fetch(request, env) {
    const origin = request.headers.get("Origin") || "";
    const cors = {
      "Access-Control-Allow-Origin": ALLOWED_ORIGINS.includes(origin) ? origin : "null",
      "Access-Control-Allow-Methods": "POST, OPTIONS",
      "Access-Control-Allow-Headers": "Content-Type",
    };
    if (request.method === "OPTIONS") return new Response(null, { headers: cors });
    if (request.method !== "POST") return new Response("Method Not Allowed", { status: 405, headers: cors });

    const body = await request.json();                    // 前端组好的 OpenAI 兼容请求体
    const resp = await fetch(UPSTREAM, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": `Bearer ${env.DEEPSEEK_API_KEY}`, // key 只在服务端环境变量
      },
      body: JSON.stringify(body),
    });
    return new Response(resp.body, { status: resp.status, headers: { ...cors, "Content-Type": "application/json" } });
  },
};
```

部署：`wrangler deploy` 后把 `DEEPSEEK_API_KEY` 写进 Worker 的环境变量（`wrangler secret put DEEPSEEK_API_KEY`）。前端 `LLMClient` 端点常量覆盖为该 Worker URL；Origin 白名单防蹭用；演示量级免费额度足够，不引入账号/数据库。

**CORS 注意事项汇总**：① 直连模式成败取决于上游端点的 `Access-Control-Allow-Origin`（W0-3 实测）；② 代理模式 CORS 由 Worker 自己控制（上面的白名单）；③ 前端代码**永远不**手动带 `Authorization` 以外的凭证头，避免触发复杂预检；④ 预检（OPTIONS）失败归入「网络失败」走离线兜底（FR-M-08 AC2），不卡死。

**离线兜底（两条路径共用）**：`qa_fallback.json`（34 条）原样复用；命中最多者胜、平票取先、零命中取兜底行、「（离线模式）」角标由调用方追加——UT-M09 语义逐条保留。

### 9.5 断网可玩性口径与 PWA 决策

- **验收基线（FR-B-02）**：首次完整加载后拔网线，游戏全流程可玩、导师走离线兜底且带「（离线模式）」。仅靠浏览器 HTTP 缓存通常可满足单次会话内断网。
- **PWA（Service Worker 离线缓存）列为可选增强（P2）**：让"关掉浏览器再打开、无网也能进游戏"成立。W4 时间富余则做（`vite-plugin-pwa`，预缓存 `dist/` 全部静态资源）；不做不阻塞验收；**首版默认不纳入**。
